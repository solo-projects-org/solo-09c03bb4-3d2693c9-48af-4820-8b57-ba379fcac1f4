# 拆并股收盘价折算（FastAPI + SQLite）

研究员复盘拆并股前后走势时，统一收盘价的股份口径。单股日收盘价（分）与拆并股公告
一次导入 SQLite；选区间和基准交易日，系统按基准日口径折算每日收盘价，四舍五入到分；
可锁定预览取得送审号，公告更正或进程重启后凭送审号仍能重现原序列。

对照两份研报时，可把同一段行情按**两个基准交易日并排**预览：首次预览一次性载入
原价与公告依据（取自同一已提交状态），之后换对照日只交换核验信息与必要换算比例，
网页复用已载入的原价按精确分数折算，最后才四舍五入到分；两列均可走原送审入口。

## 双基准日对照（本次新增）

- **快照一致**：预览/换日/送审的读取包在显式事务里，公告与行情取自同一已提交状态；
  送审的校验与落库在同一事务内原子完成。
- **两列基准日校验**：两个基准日都须是区间内有收盘价的日期（`rebase` 与 `preview`
  同一套校验，422 退回越界或无行情的日期）。
- **换日轻量通道** `GET /api/adjustments/rebase`：只回核验信息（`basis_hash`、
  `prices_hash`、`stale`、`note`）与逐日换算比例（精确分数字符串），不回行情与折算
  结果。网页缓存首次载入的原价，用 BigInt 精确乘分数因子，最后才四舍五入到分
  （`round_half_up(p·n/d) = ⌊(2pn+d)/(2d)⌋`，无浮点误差）。
- **连续换日以最后一次选择为准**：每列独立请求序号，过期响应直接丢弃。
- **补录/变更检测**：`prices_hash` 为区间行情指纹（底表只增不改，补录即变）。
  换日返回 `stale=true` 并注明“区间内行情有补录 / 现行公告已变更”；送审时指纹与
  现行不符则 409 拒绝，须刷新后重新送审。
- **双列送审**：两列共用 `POST /api/submissions`，按所选列基准日锁定；返回序列
  按所送基准日重算，网页逐点核对与所选列一致。

## 折算口径

公告：生效日起 `old_shares` 股换成 `new_shares` 股，记 `r = new/old`，价值守恒
`P_old = r × P_new`。对交易日 d 与基准日 b：

| d 口径 | b 口径 | 因子 |
|---|---|---|
| 旧（d < 生效日） | 新（b ≥ 生效日） | `1/r = old/new` |
| 新 | 旧 | `r = new/old` |
| 同口径 | 同口径 | `1` |

多个公告按生效日连乘；全程 `Fraction` 精确计算，结果按“四舍五入”（小数部分 ≥ 0.5 进位）
取整到分，不使用浮点。

## 业务规则

- **行情底表** `prices`：按交易日唯一；同日期同价重复导入跳过，异价整批退回（409），
  底表只增不改不删，更正与送审共用，不复制行情。
- **公告** `announcements`：每号只保留最高修订（表中即现行版本），全部收发留审计流水
  `announcements_log`：
  - 同号同版原样重送 → `reused` 沿用原公告；
  - 同号同版异文 → 409 退回（`rejected_diff`）；
  - 更高修订 → `updated` 更正现行版本；
  - 低于现行修订 → 422 退回（`rejected_old`）。
- **预览** `GET /api/adjustments/preview`：返回折算序列、参与折算的公告依据、依据指纹
  `basis_hash` 与区间行情指纹 `prices_hash`；带旧指纹调用时返回 `stale=true`，
  提示须刷新。
- **换日** `GET /api/adjustments/rebase`：换对照基准日的轻量通道，只回双指纹、
  `stale` 与逐日换算比例，不回行情。
- **锁定送审** `POST /api/submissions`：指纹（公告依据 + 区间行情）与现行不一致时
  409 拒绝；成功后生成 `SB-xxxx` 送审号，并在 `submission_basis` 只留重算所需的
  公告快照（生效日不晚于区间起、或晚于区间止/基准日的公告对相对因子恒为 1，不留底）。
- **凭号重开** `GET /api/submissions/{id}`：快照依据 + 同一行情底表重算，公告更正或重启后
  序列与锁定时逐点一致；同时回现行指纹与 `stale` 标记供比对。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/prices/import` | 批量导入日收盘价（分） |
| GET | `/api/prices` | 查询底表（可选 start_date/end_date） |
| POST | `/api/announcements/import` | 导入/重送/更正公告 |
| GET | `/api/announcements` | 现行公告（每号最高修订） |
| GET | `/api/adjustments/preview` | 区间折算预览（参数 start_date, end_date, base_date, 可选 basis_hash, prices_hash） |
| GET | `/api/adjustments/rebase` | 换对照日：只回双指纹、stale 与逐日换算比例 |
| POST | `/api/submissions` | 锁定预览，取得送审号（双列共用，按所送基准日锁定） |
| GET | `/api/submissions/{id}` | 凭送审号重开，重现原序列 |
| GET | `/api/health` | 健康检查 |
| GET | `/` | 网页（导入、双基准日对照预览、双列送审、凭号重开） |

## 启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 库文件持久化在宿主机 `./data/app.db`（compose 已挂载卷）。

## 本地无 Docker 时运行

```bash
pip install -r requirements-dev.txt
export APP_DB_PATH=./data/app.db
uvicorn app.main:app --host 0.0.0.0 --port 8000
pytest -q
```

## 已知遗留/约束

- 单股模型：底表未设股票代码，多股场景需扩展表结构与接口字段。
- 无鉴权/用户体系，送审号为不可猜随机号（UUID 前 16 位），仅适用于内网可信环境。
- 公告生效日按自然日比较；若生效日非交易日，按题意仍自该日起生效（首个晚于它的
  交易日适用新口径），未额外校验公告日历。
- 容器运行时在当前环境不可用，未实跑 `docker compose build`，仅做了 compose 配置静态
  校验与等效的 uvicorn 实进程冒烟（导入→双列预览→换日→补录→stale→409→刷新→双列
  送审→凭号重开全链路通过）。
- 区间行情指纹 `prices_hash` 随区间长度线性计算，超大区间（数万交易日）可改增量
  指纹；送审请求暂允许不带 `prices_hash`（兼容旧客户端），如需强制可在后续版本收紧。
